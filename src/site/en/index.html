GENERATE WITH CREXE

You have the file.
Generate its reader.

Select an ordinary document. CREXE generates or reuses an application that opens that file, without needing you to write a recipe.

SELECT

Start with the document.

Use Gerar com CREXE in the Windows context menu or Selecionar arquivo e gerar programa… in the engine window. The file picker is also the graphical entry point on macOS and Linux.

Valid unknown extensions are accepted; missing or invalid extensions receive an unsupported-type message.
GENERATE

The extension becomes intent.

Of the document's data, the engine sends only the extension to the model. One call prepares the reader's specification; generation, compilation, tests and repairs follow. Planning does not consume a code attempt.

The first generation requires a model and SDK and may take a few minutes.
REUSE

Your file, already open.

The application receives the selected document and reads its contents on your machine. Another file of the same compatible type reuses the approved reader, without generation while the cache remains valid.

Reading in this preview; opaque formats may appear as text or hexadecimal.
Use the command line

From the extracted package directory, after configuring your model and preparing the SDK:

Windows · PowerShell.\crexe.exe open-generating -- "meeting notes.md"

macOS and Linux./crexe open-generating -- "meeting notes.md"

If you built the engine from source, use the executable in target/release. For .crexe recipes, .crexp packages, and .crexb bundles, open them normally or use crexe exec recipe.crexe; Generate with CREXE shows a message without executing the recipe.

The initial contract asks for read-only access and preservation of the original. Generated applications run with your permissions; there is no security isolation. This preview does not provide a Finder/GNOME menu.

Keep as the default program on Windows

Use Gerar com CREXE e Manter como Programa Padrão in the context menu. The approved reader is preserved outside the cache. Check the program and confirm the choice in Windows Settings; other documents with the same extension then open by double-click, without an LLM or recompilation.

Read-only preview. Windows confirmation is required; closing Settings does not apply the choice. Read the guide and limitations.

How do I verify a download?

Download the package and its .sha256 file. Compare the calculated hash with the file’s contents. Both values must match. A checksum verifies integrity; it is not the author’s signature.

Windows · PowerShellGet-FileHash .\package-name.zip -Algorithm SHA256

macOSshasum -a 256 package-name.tar.gz

Linuxsha256sum package-name.tar.gz

Release notes

FROM YOUR FIRST FILE TO YOUR FIRST WINDOW

Prepare.
Describe.
Run.

The engine does not include AI models or SDKs. Configure your provider and prepare the profile’s tools before generating an app.

See profiles and requirements

Windows: .NET 8 SDK for Windows Forms. To build the engine from source, install Rust/Cargo and the Visual C++ linker.

  1. Build the engine from source

    Extract the source ZIP. In the extracted folder, run:

    cargo build --release --locked

  2. Configure and check the environment

    Choose local Ollama or a remote provider. Diagnostics do not call AI.

    .\target\release\crexe.exe configure
.\target\release\crexe.exe doctor --check

  3. Open your first recipe

    Use the example already included in the source code. This command starts generation, compilation and execution.

    .\target\release\crexe.exe examples/plaintext/calculadora.crexe

The first generation may take a few minutes. Quality depends on the model. The profile’s SDK is still needed to compile the programs.

Licensing and ecosystem

TRANSPARENCY FROM THE START

In development.
With clear limits.

Does CREXE isolate the program from my machine?

No. Compilation and execution use the host with the user’s permissions. The temporary folder organizes files but does not isolate processes, network access or data. Run only recipes and code you trust. Read the security limits.

Does it work offline?

Generation with Ollama can run locally. After preparing the model, SDKs and dependencies, this workflow can work offline. Downloads and dependency restoration may require a network connection. Remote providers require connectivity and may charge for usage.

Do I need to install Rust to use CREXE?

Only to build the engine from source. A compiled engine package does not require Rust or Python, but generated applications still need their profile’s tools. Docker and WSL are not required.

Does a recipe always generate the same program?

No. Models and generation runs can produce different implementations. To share the exact approved source code, export the project. On the same machine, reopening an unchanged recipe reuses the validated revision in the cache.

Can I sell generated apps under a proprietary license?

Yes. You choose the app’s license, including a proprietary license, and can sell it without publishing its source or crediting CREXE. The engine uses MIT: preserve its copyright and license notices when redistributing it. CREXE materials incorporated into output use MIT-0.
