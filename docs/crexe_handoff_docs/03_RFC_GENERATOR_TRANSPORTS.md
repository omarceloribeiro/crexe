# CREXE Generator Transports

**Status:** Draft 0.1  
**Purpose:** Define online LLM generator transports for CREXE v1.

---

## 1. Abstract

CREXE uses a generator to convert prompt specifications into project files.

This document defines two supported transports:

- `chat_completions`
- `responses`

The Responses transport is required for models that do not support Chat Completions, such as `gpt-5.5-pro`.

---

## 2. Generator configuration

Common fields:

```yaml
generator:
  mode: "online"
  provider: "openai"
  transport: "responses"
  baseUrl: "https://api.openai.com/v1"
  apiKeyEnv: "OPENAI_API_KEY"
  model: "gpt-5.5-pro"
  maxOutputTokens: 6000
```

---

## 3. Chat Completions transport

Transport:

```yaml
transport: "chat_completions"
```

Endpoint:

```text
POST /v1/chat/completions
```

Payload:

```json
{
  "model": "model-id",
  "messages": [
    { "role": "system", "content": "..." },
    { "role": "user", "content": "..." }
  ],
  "max_completion_tokens": 6000
}
```

Some models may require:

```json
"max_tokens": 6000
```

Runtime SHOULD support automatic fallback:

1. try configured/default token parameter
2. if rejected, switch between `max_tokens` and `max_completion_tokens`
3. if `temperature` rejected, retry without it

---

## 4. Responses transport

Transport:

```yaml
transport: "responses"
```

Endpoint:

```text
POST /v1/responses
```

Payload:

```json
{
  "model": "gpt-5.5-pro",
  "input": [
    {
      "role": "system",
      "content": [
        { "type": "input_text", "text": "..." }
      ]
    },
    {
      "role": "user",
      "content": [
        { "type": "input_text", "text": "..." }
      ]
    }
  ],
  "max_output_tokens": 6000
}
```

Optional reasoning:

```json
"reasoning": { "effort": "high" }
```

---

## 5. Responses text extraction

The runtime SHOULD extract output text in this order:

1. `output_text`
2. concatenate `output[].content[].text`

Pseudo-code:

```rust
fn extract_responses_text(json: &Value) -> Result<String> {
    if let Some(text) = json.get("output_text").and_then(Value::as_str) {
        return Ok(text.to_string());
    }

    if let Some(output) = json.get("output").and_then(Value::as_array) {
        let mut result = String::new();

        for item in output {
            if let Some(content) = item.get("content").and_then(Value::as_array) {
                for c in content {
                    if let Some(text) = c.get("text").and_then(Value::as_str) {
                        result.push_str(text);
                    }
                }
            }
        }

        if !result.trim().is_empty() {
            return Ok(result);
        }
    }

    bail!("Could not extract text from Responses API output")
}
```

---

## 6. Output parsing

After extracting text, the runtime MUST parse it as JSON matching the CREXE output contract:

```json
{
  "files": [
    { "path": "relative/path", "content": "file content" }
  ]
}
```

If the model wraps JSON in code fences, the runtime MAY strip fences in permissive mode.

---

## 7. gpt-5.5-pro recommendation

For `gpt-5.5-pro`, use:

```yaml
generator:
  mode: "online"
  provider: "openai"
  transport: "responses"
  baseUrl: "https://api.openai.com/v1"
  apiKeyEnv: "OPENAI_API_KEY"
  model: "gpt-5.5-pro"
  maxOutputTokens: 6000
  reasoning:
    effort: "high"
  sendTemperature: false
```

---

## 8. Fingerprint implications

The fingerprint SHOULD include:

- provider
- transport
- model
- `maxOutputTokens`
- reasoning effort
- temperature if used

This prevents reusing cache generated by a different model or endpoint.

---

## 9. Conclusion

CREXE SHOULD support both `chat_completions` and `responses`.

The Responses API is the preferred path for newer high-intelligence models and models that do not support Chat Completions.
