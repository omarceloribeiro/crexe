# The Creative Executable Manifesto

> Manifesto • editorial perspective • 24/11/2026

We want to bring people closer to the tools they use. A need can begin as a sentence, acquire criteria, become a recipe, and find an implementation. CREXE explores this path with a central idea: keeping intent accessible while software is created, tried, and transformed.

**Creative Executable** expresses a direction. A `.crexe` file should invite reading and participation. Someone receiving a recipe may want to use it, understand its decisions, or propose another version. The experience of running it and the possibility of editing it belong to the same conversation.

## Intent deserves to remain visible

A clear request helps people recognize what a program should do. We want descriptions that expose behavior, limits, and acceptance criteria. Natural language can bring people closer to creation, but also introduces ambiguities. Making them visible and resolving them is part of the work.

Writing a recipe is a form of design. Trying the result, noticing a need, and revising the request are also acts of creation. We want tools that make this workflow understandable, including when an attempt fails.

## A recipe can circulate; a version can be preserved

Sharing intent allows implementations to be explored. Exporting source files allows a concrete realization to be preserved and studied. Distributing a binary remains useful when that is the result one wants to deliver. These possibilities can coexist and serve different needs.

We want the choice to be explicit. Reusing an approved revision, editing a request, and starting another generation are decisions with different effects. The user should be able to understand what will be preserved and what still needs verification.

## The environment must be respected

Each platform has tools, resources, and limits. Generating an application locally requires recognizing those conditions. An intent to be portable does not remove SDKs, dependencies, integration work, or real-world trials.

We want clear diagnostics when a requirement cannot be met. Compatibility must be demonstrated for the stated environment. A desired adaptation remains a hypothesis until it works under the necessary conditions.

## Creativity needs responsibility

A successful compilation does not establish all of an application's behavior. Tests, source review, and observation of use need to accompany creation. We want to be able to identify errors, preserve useful versions, and learn from unsuccessful attempts.

The current engine runs programs with the user's permissions and does not provide security isolation. That limit must remain clear. The ambition to create more possibilities requires precise descriptions of available controls, as set out in the [execution limits](../SECURITY.md).

## Openness requires concrete commitments

The engine uses MIT to facilitate adoption, ports and integration into other projects. Formats, source files, and documentation should make it possible to understand the project and discuss its evolution. An intent to be open also requires clear contracts, responsible contributions, and respect for incorporated content.

Users choose the generated program's license, including a proprietary license. CREXE does not require publishing source code or receiving credit for its designated materials incorporated into output and official recipes, offered under MIT-0. Redistributing the engine itself requires preserving its MIT notices. Terms of dependencies, assets, third-party recipes and the model/provider still apply. The [licensing record](../LICENCIAMENTO_E_ECOSSISTEMA.md) details that scope.

## The future is shared work

CREXE is under development. This manifesto presents an editorial vision, without declaring an approved standard or promising that every description will produce a suitable program.

We want to build a workflow in which more people can formulate needs, try solutions, and share what they have learned. Readable recipes, accessible source files, and verifiable results give shape to that intent.

**Download intent. Execute creativity.**
